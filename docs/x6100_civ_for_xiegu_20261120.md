# X6100 CI-V and wfview: what to fix and implement

Date: 20261120

For Xiegu (Jin), for the CI-V rewrite of the X6100 APP. Based on a test of the stock
firmware with its own wfserver and wfview over the LAN (as an IC-705 at address `A4`,
and with the X6100 rig file at address `61`), compared with x6100_trx, an open front end
for the X6100 that answers the same commands.

With this list: `X6100.rig`, a wfview rig file for the X6100 (CI-V address `61`, hamlib
model 3087). It is wfview's IC-705 file without the functions the X6100 lacks: wfview
then neither polls them nor shows controls that do nothing. Copy it into wfview's rig
directory and set the radio to address 61.

## 1. Broken now (stock firmware 20261120)

In order of how much they hurt:

1. **LAN audio**: no RX audio in wfview and no TX audio from it. wfview PTT keys the
   radio, but nothing is modulated. This is what most users report.
2. **VFO A / B**: the receiver is on the VFO that is not shown. The radio and wfview both
   show 3630 kHz (80 m) while 1179 kHz (MW) is heard, and the other way round. Each
   wfview disconnect / connect swaps A and B; after VFO select (07 00 / 01) the radio
   behaves oddly. Probably 25 00 / 01 and 26 00 / 01 (selected / unselected VFO) or
   07 00 / 01 use the wrong VFO.
3. **Band stacking register (1A 01)**: a wfview band button (40 m to 20 m) sends the
   radio to 500 kHz. Band up / down on the radio with wfview connected makes it fail,
   once the UI restarted. The band codes must be the IC-705's (01 = 1.8 MHz ... 15 =
   general coverage).
4. **AGC (16 12)**: values shifted. wfview MID sets SLOW, SLOW sets AUTO, FAST is right.
   IC-705: 01 fast, 02 mid, 03 slow (the X6100's AUTO is best read as 02).
5. **Transceive**: only frequency changes are sent unasked. A change on the radio of the
   mode, AGC, tuning step, RF gain, squelch, preamp, attenuator, NR or NB reaches wfview
   late (its poll) or never. On an Icom every such change goes out to address 00 (see 3).
6. **Tuning step (10)**: no effect from wfview; a change on the radio not seen.
7. **Tuner (1C 01)**: tune works, but the read gives off while the radio shows ATU on.
8. **Filter width (1A 03)**: wfview shows one fixed width.
9. **Memories (1A 00)**: the wfview memory window does not work. The format x6100_trx
   answers, and wfview reads, is in `x6100_civ.md`, section 3.
10. **Scope**: hold (27 17) does not work; the mode (27 14) is not read back and cannot be
    set from wfview, although a change on the radio does reach wfview's scope.

Works: frequency both ways, mode, filter and data mode from wfview, split, RIT, A <-> B
(07 B0), S-meter, PTT both ways, power on / off, scope and waterfall, reference level,
AF / RF gain, squelch, ATT, PRE, NB and NR from wfview, ATU tune.

## 2. Missing (IC-705 commands the X6100 can do)

Not in the Xiegu CI-V reference, used by wfview or hamlib, all done in x6100_trx:

- 07 A0: VFO A = VFO B (wfview A=B button)
- 0F 10 / 11 / 12: simplex / DUP- / DUP+ (repeater duplex)
- 1C 03: read the TX frequency (split and duplex)
- 0E: scan, on the squelch: 00 stop, 01 programmed or memory scan (memory scan in memory
  mode, else the programmed range: wfview's scan button sends 01), 02 programmed, 22 / 23
  memory / select memory, D0 / D3 resume off / on
- 28 00: voice TX memory (here: the messages), hamlib `send_voice_mem`
- 17: send CW text (and 17 FF to stop), buffered as on an Icom
- 1A 05 0118 / 0119: DATA OFF MOD / DATA MOD input including 03 (LAN): the TX audio
  from wfview when CAT keys, the mic for the PTT key
- 1A 05 0165 / 0166 / 0170: date, time, UTC offset (wfview Set Clock)

The full list per command (IC-705, the Xiegu reference, x6100_trx) is in
`x6100_civ_compare.md`; the byte formats in `x6100_civ.md`.

## 3. Behaviour clients rely on

- **Transceive**: every change made on the radio goes out to address 00: frequency (00),
  mode (01), and the levels and switches (14 xx, 16 xx, 11, 0F, 27 17). A client that made
  the change itself does not get it echoed back.
- **Broadcast**: 19 00 sent to address 00 is answered with the radio's address (wfview
  finds the radio that way); other commands to 00 are carried out but not answered.
- **NG, not silence**: a command the radio does not have is answered `FA` at once. Silence
  makes the client wait for its timeout on every poll.
- **One VFO model**: 07 00 / 01, 25 / 26 00 / 01, 07 B0 and the receiver must all agree on
  which VFO is in use; a reconnect must not change it.
- **Memories read only from CAT** unless the user allows writing (a menu switch): any
  client on the port can otherwise overwrite or clear every channel.
