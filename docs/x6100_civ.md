# X6100 CI-V — command set

Status: 2026-10-23. Engine in `src/x6100_civ.c` (`include/x6100_civ.h`), host test
`tests/x6100_civ_test.c`. Wired to x6100_trx over the USB serial port
(`x6100_trx --cat`); untested on the radio. The radio announces itself as an
**IC-705** (address `A4`): set wfview / the client to IC-705.

Sources, in order of authority:

1. **Behaviour:** *IC-705 CI-V Reference Guide* (Icom, ENG CI-V 6). For every
   command we implement, the IC-705 behaviour is what clients expect.
2. **Command set of the X6100:** *XIEGU RADIO CI-V REFERENCE* v1.0 (X6100, G90,
   G106). Where it differs from the IC-705, the IC-705 wins; Xiegu-only commands
   (1D 19) are kept.
3. **Cross-check only:** x6100_gui `src/cat/civ_processor.cpp` (LGPL-2.1). No code
   taken.

## 1. Framing

```
FE FE <to> <from> <cmd> [<sub>] [<data> ...] FD
```

| Item | Value |
|---|---|
| OK / NG | `FB` / `FA` |
| Radio address | `A4` (IC-705) |
| Controller | any; replies go to the sender's address |
| To `00` (broadcast) | acted on, never answered |
| Own address as sender | ignored (echo) |
| Levels / meters | 2 bytes BCD `0000`-`0255`, most significant first |
| Frequency | 5 bytes BCD, least significant pair first, 1 Hz |
| Transceive | radio sends `00` (frequency) and `01` (mode, filter) to `00` on every change |

## 2. Modes

| CI-V | Mode | libx6100 |
|---|---|---|
| 00 | LSB | `X6100_MODE_LSB`, with data on `X6100_MODE_LSB_DIG` |
| 01 | USB | `X6100_MODE_USB`, with data on `X6100_MODE_USB_DIG` |
| 02 | AM | `X6100_MODE_AM` |
| 03 | CW | `X6100_MODE_CW` |
| 05 | FM | `X6100_MODE_NFM` |
| 07 | CW-R | `X6100_MODE_CWR` |

04 RTTY, 06 WFM, 08 RTTY-R, 17 DV: NG. Data mode only on LSB / USB.

Filter byte 01 / 02 / 03 = FIL1 / FIL2 / FIL3.

## 3. Implemented

"Xiegu" column: in the Xiegu reference (**y**) or IC-705 only (**705**).

### 3.6 1A

| Sub | Data | Function | Notes |
|---|---|---|---|
| 03 | (none) / index | IF filter width of the selected filter | SSB / CW: 00-09 = 50-500 Hz, 10-40 = 600-3600 Hz; AM: 00-49 = 200-10000 Hz (both sidebands); FM: NG. Set changes BW around the current centre and saves it (as the filter panel) |
| 06 | (none) / data, fil | data mode and filter | read with data off: 00 00. Set 00 00: data off, filter kept |
| 01 | band, register (BCD) [content] | band stacking register | band codes 01-10 (1.9-50 MHz; no 60 m): read returns the band's last frequency (the band memory), its mode (current mode on the current band, else LSB below 10 MHz / USB above), FIL; registers 01-03 are the same. Set stores the frequency. 11-15: NG |
| 00, 02, 04, 05, others | | memories, keyer, AGC time constant, menu | NG |

Our filter maximum is 6000 Hz: wider values are clipped.

### 3.7 1C: TX, tuner

| Sub | Data | Function | Notes |
|---|---|---|---|
| (none) / 00 | | read TX status | 00 RX / 01 TX |
| 00 | 00 / 01 | PTT off / on | OK, not status |
| 01 | (none) | read tuner | 00 off, 01 on, 02 tuning |
| 01 | 00 / 01 / 02 | tuner off / on / tune | |
| 03 | | read TX frequency | |

x6100_trx: CAT PTT during a tune aborts the tune (as the PTT key; no TX, OK reply,
TX status stays 00). Otherwise CAT PTT works like a latched PTT tap, with the same band check, TX
timeout and SWR trip; PTT off or any front panel key drops it. `x6100_rx` answers
NG. CAT PTT sets the PTT flag (register 12 `0x40000`): microphone in voice modes;
in USB-D / LSB-D the rear line / USB audio is presumed (untested). Network audio
will use codec TX (`0x4000`), see `x6100_netaudio_design.md` §4.

### 3.8 21: RIT / XIT

| Sub | Data | Function | x6100_trx |
|---|---|---|---|
| 21 00 | [offset] | RIT / XIT offset, one for both (±9.999 kHz, BCD + sign) | ±9990 Hz; AGC long panel |
| 21 01 | 00 / 01 | RIT off / on | RX = selected VFO + offset |
| 21 02 | 00 / 01 | XIT off / on | TX = TX VFO + offset |

The baseband RIT / XIT registers (42 / 43) are not used: x6100_trx moves the RX and
TX frequencies itself, which also covers split.

### 3.9 27: scope (IC-705)

| Sub | Data | Function | x6100_trx |
|---|---|---|---|
| 00 | | waveform data, streamed (read: NG) | see below |
| 10 | 00 / 01 | scope on / off | client setting |
| 11 | 00 / 01 | wave data output on / off | client setting |
| 12, 13 | 00 | main / sub, single / dual | main, single only |
| 14 | 00 + 00-03 | CENTER, FIX, SCROLL-C, SCROLL-F | our scope mode (F1) |
| 15 | 00 + freq | half span, Center / SCROLL-C | nearest of our spans that covers it (±48 / 24 / 12 / 6 / 3 / 1.5 kHz) |
| 16 | 00 + 01-04 | fixed edge set | stored |
| 17 | 00 + 00 / 01 | hold | stops the stream |
| 19 | 00, dB, 0.1 dB, sign | reference level ±20 dB | shifts the waveform |
| 1A | 00 + 00-02 | sweep speed fast / mid / slow | 100 / 250 / 500 ms minimum |
| 1D | 00 + 00 / 01 | VBW | stored |
| 1B, 1C, 1E, 20 | | TX scope, center type, fixed edges, marker | NG |

Waveform (27 00) over serial, to the last controller that addressed us:

```
info:  FE FE E0 A4 27 00 00 01 11 <mode> <centre or lower edge, 5 B> <half span or upper edge, 5 B> <out of range> FD
data:  FE FE E0 A4 27 00 00 <02..11> 11 <50 points> FD     (11th frame: 25 points)
```

475 points, 0-160, from the same spectrum the screen draws (`spec_norm`), over
the same window as the screen (scope mode and span). One sweep is about 600 bytes:
a new one goes out only when the port's output queue is empty, so at 19200 baud
about 3 sweeps / s.

## 5. x6100_trx

```
x6100_trx --cat            CI-V on /dev/ttyS2, 19200 baud
x6100_trx --cat=115200     other speed (4800-115200); set the PC side the same
```

- The "DEV" USB-C connector holds a hub with a CH342 dual serial (1a86:55d2) and a
  C-Media USB sound card (0d8c:0012). CH342 port 1 (PC `ttyACM0`) is the Linux
  console (ttyS0); port 2 (PC `ttyACM1`) is `/dev/ttyS2`, CAT. Verified
  2026-10-23: `03` answered at 19200 on both ends (115200 on both ends did not).
- Stock image: ttyS2 runs at 19200 in hardware whatever Linux sets (termios reads
  back 115200, yet radio at 115200 with the PC at 19200 works, and 38400 on both
  ends does not). Keep 19200 on both ends; `--cat=` only helps on another kernel.
  19200 / A4 is also what clients document for the X6100 (MacLoggerDX). Scope over
  serial: about 1-3 sweeps / s.
- VFO B lives in x6100_trx (frequency, mode, filter); the baseband gets the RX
  frequency, and while keyed the TX one (split, XIT) just before PTT goes out; 07 01 /
  07 B0 swap it in, like the A/B key. The hand mic PTT keys the baseband directly;
  x6100_trx follows its TX flag, so after the first ms it transmits on the TX side too.
- Every change (panel, console or CAT) sends 00 / 01 transceive frames.
